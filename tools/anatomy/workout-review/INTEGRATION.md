## Three distinctions

- Per-tab example persistence is not persistence to an account; local success cannot represent a successful server write.
- Timers use the actual product clock/state code. That does not validate reconnect, expiring credentials or uncertain RPC results. The existing product tests retain rejected/blocked/transient cases.
- Hash navigation supports the preview only. Authorization stays in the real proxy, server guards and RLS. A working link, login page or READY deployment does not establish authorization correctness.

## Release disposition

The coach uses a separate `NEXT_PUBLIC_COACH_ASSISTANT_ENABLED=1` UI switch and `COACH_ASSISTANT_ENABLED=1` server switch, both off by default. Its Home section is excluded during live, paused, finishing and completed recovery. The private exporter keeps the public switch off and injects only the synthetic adapter. No query/provider failure falls back to example data. The first response contract is complete-response JSON, not streaming. Cancel/close/unmount abort the request and discard late replies; a 50-second client deadline bounds a hung transport. Evidence is rendered as plain text with its authorized date window, never model-provided links or HTML. Suggestions and message drafts have no write/send actions. V1 real response content is English and labelled when the UI language differs.

Coach copy follows the shared locale and interpolation through `useCoachI18n`, inside the lazy feature bundle. It is deliberately absent from the eagerly loaded global dictionary. The normal Home entry is also gated at its call site; the private composition supplies an explicit preview slot and never enables the account flag. The server additionally requires its authenticated preview-user allowlist and refuses production activation in this wave. Real plan evidence comes from active saved programs/templates, not device drafts; the UI says so. Synthetic server fixtures remain a server test adapter and are rejected by the normal account client. The exported prototype instead summarizes its own per-tab strength/cardio draft and completed records with zero API/model calls.

### Authenticated integration evidence

The manually dispatched `CI` input `coach_auth_only=true` uses the existing local Auth runner on an ephemeral standard GitHub runner, with local Supabase Auth/PostgREST/PostgreSQL and disposable identities. It preserves the real `auth.uid()` definition and uses the canonical local schema bootstrap. It does not connect to a linked Supabase project or production data, add migrations, run a model, upload new artifacts, or use a larger runner. This job is limited to the public repository. Normal CI remains a separate run and gate.

`scripts/test/run-coach-auth-e2e.mjs` supplies real authorized records to `e2e/coach-week.spec.ts`: UI week → cookie authentication → HTTP route → bounded SQL → deterministic facts → rendered sources. Cases cover sufficient, partial and missing records, real coach-cookie cross-organization/revoked authorization, a blocked SQL read/error/retry, and actual pending HTTP cancellation. The denial cases validate HTTP rather than a professional client-selector UI. The source fixtures are synthetic, while the response is correctly labelled `authorized_records` because it traverses the real repository; they are never the private prototype adapter.

The same stack runs two sequential app processes: coach enabled for the matrix, then both coach flags off. Workout checks edit/navigation, durable draft/set recovery, rest and finish; they do not establish physical iPhone performance. Test preparation archives/restores only its own disposable plan to exercise missing evidence. The assistant itself has no mutation action. The fixture wrapper cleans up owned rows and Auth users even after failure.
