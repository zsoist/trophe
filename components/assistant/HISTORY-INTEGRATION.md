# Durable conversation surface

The server gate is `COACH_ASSISTANT_CHAT_HISTORY_ENABLED=1`; the separate browser gate is `NEXT_PUBLIC_COACH_CHAT_HISTORY_ENABLED=1`. Both default off. The browser flag cannot grant database access. The self-client route checks authentication and the preview allowlist before constructing the service; the service rechecks membership and scope inside each transaction. Synthetic runtime is rejected for durable generation. An explicitly injected example transport is test-only.

An explicit first send creates a server-owned thread using a stable creation request ID and title. Only after that acknowledgement does generation start. Memory/diet controls wait for the thread when history is enabled. A received success means the generated final answer was persisted; otherwise the UI requires history recovery. A repeated claimed user turn never automatically regenerates. If the server stopped before saving an assistant answer, the real user message remains unanswered; the user can reopen and send a new explicit follow-up. This is not automatic recovery of the missing generated text.

Stored messages are rendered separately from live response metadata. Reopening does not fabricate current evidence, upload permissions, memory tokens or profile state. Only six bounded history snippets enter the existing prompt path; stored assistant messages carry no invented derived-history token. Reading all pages is required before continuing. A revision change between pages discards the partial transcript and requires reloading.

New conversation and account changes abort pending requests and clear local transcript and contextual controls. Close unmounts pending history reads. Rename uses the current server revision and reload after an uncertain result. Delete requires explicit review; associated cleanup may remain pending. Applied profile/food/workout changes are outside conversation erasure. Private storage removal is not connected in the route yet; nonempty uploads must remain pending.

Current evidence: focused UI/service/offline tests; real Auth/history E2E prepared and wired only into disposable CI. No production schema installation, public flag activation, paid-provider quality result or cross-device test is implied. Pending cleanup discovery after reload is integrated and source-reviewed. Privacy sidecar export/erasure and real history runtime verification remain release requirements.
